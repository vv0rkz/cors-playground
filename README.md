## Участники

- **Фронтенд #1** — `http://localhost:3000`
- **Фронтенд #2** — `http://localhost:5173` (тот же самый статический код, просто на другом порту)
- **Бэкенд** — `http://localhost:4000`

## Условие

Один и тот же бэкенд теперь обслуживает два разных фронта — это нормальная ситуация (например, staging и prod, или веб-версия и админка). Открой оба адреса в браузере:

- `http://localhost:3000` — работает, JSON отображается.
- `http://localhost:5173` — падает с той же самой ошибкой `blocked by CORS policy`, что и в самой первой версии (v1.0).

## Задача

1. Посмотри, что стоит в `Access-Control-Allow-Origin` на ответе (Network → Response Headers) для запроса с `5173`.
2. Подумай, почему нельзя просто вписать туда оба origin через запятую (`'http://localhost:3000, http://localhost:5173'`) — попробуй, если сомневаешься, и посмотри, что скажет браузер.
3. Пойми идею: `Access-Control-Allow-Origin` может содержать только **одно** значение (конкретный origin или `*`) — сервер не может статически захардкодить список. Значит, значение заголовка нужно формировать **динамически**, на основе того, откуда реально пришёл запрос.
4. Почини на сервере — [server/server.js](server/server.js). Пригодится `req.headers.origin` — это то, что браузер сам присылает в каждом запросе.

**Подсказка, если застрял:** заведи список разрешённых origin (`allowedOrigins`), сравни с ним `req.headers.origin`, и если он в списке — подставь именно его (не список целиком!) в `Access-Control-Allow-Origin`.

**Как понять, что фикс сработал:** оба адреса — `3000` и `5173` — открывают страницу без ошибки в консоли и с JSON на экране.

---

## Решение

`Access-Control-Allow-Origin` физически не может содержать список — там ровно одно значение (конкретный origin или `*`). Поэтому «несколько разрешённых origin» — это не фича заголовка, а логика на сервере: заголовок формируется заново на каждый запрос, в зависимости от того, кто именно спрашивает.

```js
const allowedOrigins = ['http://localhost:3000', 'http://localhost:5173']

app.get('/api/data', (req, res) => {
  const requestOrigin = req.headers.origin
  if (allowedOrigins.includes(requestOrigin)) {
    res.set({ 'Access-Control-Allow-Origin': requestOrigin })
  }
  res.json({ message: 'Hello from backend', timestamp: Date.now() })
})
```

Сервер читает `Origin` из заголовков **входящего** запроса (браузер присылает его сам, подделать его со стороны JS нельзя), сверяет со своим списком и, если совпадение есть, **отражает** его обратно в `Access-Control-Allow-Origin` — то есть значение заголовка каждый раз разное, но всегда равно ровно тому origin, который спросил.

**Вывод:** whitelist — это паттерн "echo origin, если он в списке", а не особый синтаксис заголовка. Origin не в списке (например, `evil.com`) не получает заголовок вообще — и браузер блокирует ответ для него, как и раньше.
